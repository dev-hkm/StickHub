# StickHub 5.0 Implementation Plan

> **For agentic workers:** use subagent-driven-development for bounded parallel tasks, with root integration/review.

**Goal:** Preserve existing user data and ship a materially more reliable, responsive major release.

**Architecture:** Existing SQLite repository, Compose application screens and View-based overlay remain. Extract testable safety/interaction policies, own asynchronous work by lifecycle, and avoid overlapping file ownership.

**Tech Stack:** Kotlin, existing Compose Material 3/Lucide/Coil/ML Kit stack; JUnit plus Robolectric 4.16.1 for device-less Android tests.

## Global Constraints

- Preserve applicationId, signing identity, current sticker files and DB; no destructive migration.
- No new theme, cloud feature, emoji, or unrelated design-doc edits.
- Test command: JAVA_HOME=Android Studio jbr; gradlew.bat --no-daemon --max-workers=1 :app:testDebugUnitTest. This task compiles JVM tests, not a Debug APK.
- Root owns Gradle, MainActivity, StickHubApp and SettingsScreen; delegate owners must coordinate interface changes.

## Work checklist

- [x] Inventory current checkpoint, source and independent risks; start baseline tests/lint.
- [ ] Data safety: StickerRepository, BackupHelper, database/provider support and Android/file regression tests. Test postcommit cleanup, restore round trips, archive budgets, atomic edit, category integrity before changing production behavior.
- [ ] Overlay: OverlayService/rendering/layout policy tests. Cover closed rotation, cancel stale grid loads, finite input bounds and recoverable independent alpha. Do not change Settings integration.
- [ ] Library/cutout: SubjectCutoutProcessor, SubjectCutoutSheet, CategoryChips and pure state regression tests. Root wires suspend save callback. Test request replacement, huge aspect ratios and reorder-cancellation semantics.
- [ ] Settings/lifecycle: new OverlayAppearance/preview dispatch policy plus slider tests; wire transient Intent extras, commit-only preferences, presets, resumed clipboard observation, honest background-operation status and permission recovery.
- [ ] Root review each diff against acceptance contract; run regression red/green evidence, full JVM suite, lint Release; resolve actionable findings.
- [ ] Version, signed Release APK, archive/APK/signature checks; R2 public verification and one ntfy. Commit checkpoint and publish scoped release notes with device-test limitations.

## Interfaces owned by root

Cutout `onSaveSticker: suspend (Bitmap, String, String, String) -> Boolean`; the sheet controls its saving/error/dismiss state. Root performs persistence and returns success without closing on failure.

Overlay transient preview uses an appearance-layer identifier and float value in ACTION_PREVIEW_APPEARANCE; ACTION_UPDATE_APPEARANCE restores committed state. Root and overlay owner agree constants before edits. Never serialize credentials in docs or source.
